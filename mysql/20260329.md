## [テーブルの値を全削除]

**MySQL の外部キー制約（FOREIGN KEY）によるエラー**

---

### なぜ TRUNCATE が失敗するのか？

あなたのエラー：

```
ERROR 1701 (42000): Cannot truncate a table referenced in a foreign key constraint (`honeycomb`.`orders`, CONSTRAINT `orders_ibfk_1`)
```

これはつまり：

- **products テーブルは orders テーブルから参照されている（外部キー）**
- そのため **TRUNCATE（高速削除）は禁止されている**

という意味です。

MySQL の仕様で、**外部キーで参照されているテーブルは TRUNCATE できません。**

---

## 解決方法は 3 つあります

###  **方法1：外部キーを一時的に無効化して TRUNCATE（最も簡単）**

```sql
SET FOREIGN_KEY_CHECKS = 0;

TRUNCATE TABLE orders;
TRUNCATE TABLE products;
TRUNCATE TABLE process_prices;

SET FOREIGN_KEY_CHECKS = 1;
```

#### ✔ これが最も一般的で安全  
#### ✔ データ移行のときによく使う方法

---

### **方法2：TRUNCATE ではなく DELETE を使う**

```sql
DELETE FROM orders;
DELETE FROM products;
DELETE FROM process_prices;
```

#### ✔ DELETE は外部キー制約を守りながら削除する  
#### ✔ ただし TRUNCATE より遅い  
#### ✔ AUTO_INCREMENT はリセットされない（必要なら後でリセット）

AUTO_INCREMENT をリセットしたい場合：

```sql
ALTER TABLE products AUTO_INCREMENT = 1;
```

---

### **方法3：外部キーを一時的に削除して TRUNCATE（非推奨）**

これはあまりおすすめしませんが、どうしても必要なら：

```sql
ALTER TABLE orders DROP FOREIGN KEY orders_ibfk_1;
TRUNCATE TABLE products;
```

ただし、後で外部キーを再作成する必要があります。

---

### あなたのケースで最適なのは？

#### **方法1：FOREIGN_KEY_CHECKS を 0 にして TRUNCATE**

データ移行の作業ではこれが最も一般的で、  
あなたのように「何度もインポートし直す」場合に最適です。

---

### 実際に使うべきコマンド（あなたのテーブル構造に合わせた版）

```sql
SET FOREIGN_KEY_CHECKS = 0;

TRUNCATE TABLE orders;
TRUNCATE TABLE products;
TRUNCATE TABLE process_prices;

SET FOREIGN_KEY_CHECKS = 1;
```

---

### これでテーブルを完全に空にできます

- 外部キーエラーは出ない  
- AUTO_INCREMENT もリセットされる  
- 再インポートがスムーズにできる
