## [一番借りているジャンルを特定する]

３つのクエリの構成で求める  
```sql
WITH customer_genre_totals AS (
  -- 1. まず「顧客がどのジャンルを何回借りたか」を集計する
  SELECT
    ct.customer_id,
    ct.first_name,
    ct.last_name,
    c.name AS genre_name,
    COUNT(*) AS rentals_in_this_genre
  FROM customer ct
  JOIN rental r ON ct.customer_id = r.customer_id
  JOIN inventory i ON r.inventory_id = i.inventory_id
  JOIN film_category fc ON i.film_id = fc.film_id
  JOIN category c ON fc.category_id = c.category_id
  -- 顧客とジャンルでグループ分け
  GROUP BY ct.customer_id, c.category_id
),
analytical_summary AS (
  -- 2. ここでウィンドウ関数を使う
  -- ここでは「1つの行 ＝ 1つのジャンル」になっているので、COUNT(*) がジャンル数になる！
  SELECT
    *,
    -- 顧客ごとの全レンタル合計(後で割合を出すため)
    SUM(rentals_in_this_genre) OVER(PARTITION BY customer_id) AS total_rentals,
    -- 顧客のジャンルの種類数
    COUNT(*) OVER(PARTITION BY customer_id) AS total_genres,
    -- 顧客のジャンルの種類数にランク付けをする
    ROW_NUMBER() OVER(PARTITION BY customer_id ORDER BY rentals_in_this_genre DESC) AS genre_rank
  FROM customer_genre_totals
)
-- 3. メインジャンルのみを抽出して指標を計算
SELECT
  customer_id,
  first_name,
  last_name,
  genre_name AS main_genre,
  rentals_in_this_genre AS main_genre_count,
  total_rentals AS r_num,
  total_genres AS c_kinds,
  -- メインジャンルが全体の何割を占めるか(依存度)
  ROUND(rentals_in_this_genre / total_rentals * 100, 1) AS main_genre_dependency,
  -- 1ジャンルあたりの平均レンタル数(密度)
  ROUND(total_rentals / total_genres, 2) AS genre_density
FROM analytical_summary
WHERE genre_rank = 1  --1位のみ抽出
ORDER BY main_genre_dependency DESC;
```

### コードの解説とポイント

「メインジャンル（その人が最も多く借りているジャンル）」を特定するには、「顧客×ジャンルごとの貸出数」を計算した上で、  
その中から「1位」を選び出すという処理が必要になる  
このクエリでは、まず顧客ごとのジャンル別集計を行い、その中で「一番借りているもの」に順位をつけて抽出  

### 1.ステップを分ける

「1回の集計ですべて出そう」とせず、「まず顧客×ジャンルで集計する」というステップを踏むのがコツ  
そうすれば、次のステップでは「行数 ＝ ジャンル数」になるため、`DISTINCT` を使わずに済む  
※`MySQL`ではウィンドウ関数の中で`DISTINCT`が使えない（エラーになる）  

ポイントは `analytical_summary` CTE の中でのデータの形  

1. 最初の `customer_genre_totals` で、顧客 A さんのデータが以下のようになっているとする  
* Action: 5回
* Comedy: 3回
* Drama: 2回


2. この時点で A さんに関するデータは **「3行」** ある  
3. 次に `COUNT(*) OVER(PARTITION BY customer_id)` を実行すると、A さんの 3行をカウントするので、結果は **「3」** になる  
* これが結果的に **`COUNT(DISTINCT category_id)` と同じ意味** になる

### 3. ウィンドウ関数 `ROW_NUMBER()` の応用技

`ROW_NUMBER() OVER(PARTITION BY customer_id ORDER BY rentals_in_this_genre DESC)`  
この部分は、「顧客（`customer_id`）ごとにグループを作り、その中でレンタル数が多い順に 1, 2, 3... と番号を振る」という命令  
これにより、最も借りているジャンルに必ず「1」が割り振られる  

### 4. 新しい指標 `main_genre_dependency`（メインジャンル依存度）

単に「同じジャンルを借りる」といっても、以下の2パターンでは意味が異なる

* **Aさん：** 全10回中、アクションを9回借りた（依存度90%）
* **Bさん：** 全10回中、アクションを2回借りた（依存度20%：他のジャンルもまんべんなく借りている）

この「依存度」を数値化することで、**「その顧客が特定のジャンルにどれほど忠誠心（ロイヤリティ）を持っているか」**がより鮮明に見えてくる

**(以下は前日からの抜粋)**  
> ### A. 1ジャンルあたりの平均レンタル数（密度）
>
> 「1つのジャンルに対して、どれだけ深くハマっているか」を出す指標  
> 
> * **数式:** `COUNT(r.rental_id) / COUNT(DISTINCT c.category_id)`
> * **意味:** 1ジャンルあたり何回レンタルしたか。数値が高いほど、特定のジャンルをリピートしている  
> 
> ### B. ジャンル専念度（特化率）
> 
> 今回の目的である「同じジャンルだけ借りる人」を1.0（100%）として評価する指標  
> 
> * **数式:** `1 / COUNT(DISTINCT c.category_id)`
> * **意味:** 数値が1に近いほど、浮気をせずに特定のジャンルに絞っている  

## [その他のマーケティング案]

### テーマのアイデア

#### 1. **ジャンルの多様性スコア（Diversity Score）**
- **定義**：顧客がどれだけ幅広いジャンルを借りているか。
- **実装例**：`ジャンル数 ÷ 総レンタル数` や `エントロピー` を使ってもOK。
- **面白さ**：雑食タイプか、こだわり派かが見えてくる！

#### 2. **新作志向スコア（Recency Bias）**
- **定義**：最近リリースされた映画をどれだけ好んで借りているか。
- **実装例**：`film.release_year` を使って、平均リリース年を算出。
- **面白さ**：流行に敏感な人か、クラシック好きかが分かる。

#### 3. **リピート傾向（Repeat Rate）**
- **定義**：同じ映画を複数回借りている割合。
- **実装例**：`rental` テーブルで `film_id` の重複をカウント。
- **面白さ**：お気に入りを何度も観るタイプか、新しいものを求めるタイプか。

#### 4. **レンタル頻度（Activity Level）**
- **定義**：一定期間あたりのレンタル回数（例：月平均）。
- **実装例**：`rental_date` を使って月別に集計。
- **面白さ**：アクティブユーザーか、たまにしか借りない人かが分かる。

#### 5. **ジャンルの季節性（Seasonal Preference）**
- **定義**：季節ごとに好むジャンルの傾向。
- **実装例**：`rental_date` を月ごとに分けて、ジャンルの傾向を分析。
- **面白さ**：夏はアクション、冬はドラマ…みたいな傾向が見えるかも！

#### 6. **ジャンルの変化傾向（Taste Shift）**
- **定義**：時間の経過とともに好みがどう変化しているか。
- **実装例**：年単位で主なジャンルを比較。
- **面白さ**：「昔はキッズ向け、今はサスペンス」みたいな成長（？）が見える！

#### 7. **クラスタリング（K-meansなど）**  
顧客を「ジャンル偏好タイプ」に分類  
- 「アクション特化型」
- 「バランス型」
- 「新作マニア型」
- 「懐かしの名作派」
