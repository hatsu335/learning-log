## [CASE式]

### 検索CASE式  
構文　CASE WHEN <評価式> THEN <式> ... ELSE <式> END  
※ELSEは省略可

テーブル
```bash
+-----------+----------------+---------------+--------------+--------------+------------+
| shohin_id | shohin_mei     | shohin_bunrui | hanbai_tanka | shiire_tanka | torokubi   |
+-----------+----------------+---------------+--------------+--------------+------------+
| 0001      | Tシャツ        | 衣服          |         1000 |          500 | 2009-09-20 |
| 0002      | 穴あけパンチ   | 事務用品      |          500 |          320 | 2009-09-11 |
| 0003      | カッターシャツ | 衣服          |         4000 |         2800 | NULL       |
| 0004      | 包丁           | キッチン用品  |         3000 |         2800 | 2009-09-20 |
| 0005      | 圧力鍋         | キッチン用品  |         6800 |         5000 | 2009-01-15 |
| 0006      | フォーク       | キッチン用品  |          500 |         NULL | 2009-09-20 |
| 0007      | おろしがね     | キッチン用品  |          880 |          790 | 2008-04-28 |
| 0008      | ボールペン     | 事務用品      |          100 |         NULL | 2009-11-11 |
+-----------+----------------+---------------+--------------+--------------+------------+
```
コード（`MySQL`では`CONCAT`を使用する、他データベースでは`||`を使用する）
```sql
SELECT shohin_mei,
CASE 
  WHEN shohin_bunrui = '衣服'         THEN CONCAT('A: ', shohin_bunrui)
  WHEN shohin_bunrui = '事務用品'     THEN CONCAT('B: ', shohin_bunrui)
  WHEN shohin_bunrui = 'キッチン用品' THEN CONCAT('C: ', shohin_bunrui)
  ELSE NULL
END AS abc_bunrui
FROM shohin;
```
結果
```bash
+----------------+-----------------+
| shohin_mei     | abc_bunrui      |
+----------------+-----------------+
| Tシャツ        | A: 衣服         |
| 穴あけパンチ   | B: 事務用品     |
| カッターシャツ | A: 衣服         |
| 包丁           | C: キッチン用品 |
| 圧力鍋         | C: キッチン用品 |
| フォーク       | C: キッチン用品 |
| おろしがね     | C: キッチン用品 |
| ボールペン     | B: 事務用品     |
+----------------+-----------------+
```
### 単純CASE式  
構文　CASE <式> WHEN <式> THEN <式> ... ELSE <式> END  
※ELSEは省略可  

コード(検索CASE式と同じ結果になる)
```sql
SELECT shohin_mei,
CASE shohin_bunrui
  WHEN '衣服'         THEN CONCAT('A: ', shohin_bunrui)
  WHEN '事務用品'     THEN CONCAT('B: ', shohin_bunrui)
  WHEN 'キッチン用品' THEN CONCAT('C: ', shohin_bunrui)
  ELSE NULL
END AS abc_bunrui
FROM shohin;
```

### 集計関数を使った検索CASE式  

コード
```sql
SELECT
  SUM(CASE WHEN shohin_bunrui = '衣服'         THEN hanbai_tanka ELSE 0 END) AS '衣服',
  SUM(CASE WHEN shohin_bunrui = '事務用品'     THEN hanbai_tanka ELSE 0 END) AS '事務用品',
  SUM(CASE WHEN shohin_bunrui = 'キッチン用品' THEN hanbai_tanka ELSE 0 END) AS 'キッチン用品'
FROM shohin;
```
結果
```bash
+------+----------+--------------+
| 衣服 | 事務用品 | キッチン用品 |
+------+----------+--------------+
| 5000 |      600 |        11180 |
+------+----------+--------------+
```

### [文字列結合における`||`と`CONCAT`について補足]
他のデータベースでは`CONCAT`ではなく`||`を使用することを忘れてはいけない  
SQLの標準仕様では、`||`は`「文字列結合演算子」`として定義されている  
MySQLでは`||`を`「論理OR」`として解釈する  
文字列で使うと`'A' || 'B'`は`"A" or "B"`と解釈されて、`"A"`も`"B"`も  
非ゼロの文字列（真（１））なので、結果は数値（０か１、この場合１）になる  
つまり、`WHERE`句の中では`OR`として自然に動くケースもあるが文字列結合には使えない  

## [CTE (Common Table Expression) Query内で使える一時的なテーブル]
### 再起的なCTE（階層が深くなっていくデータの処理）  

テーブル
```bash
postsテーブル
+----+---------+
| id | message |
+----+---------+
|  1 | post-1  |
|  2 | post-2  |
|  3 | post-3  |
+----+---------+

commentsテーブル
+----+---------+-----------------+-----------+
| id | post_id | comment         | parent_id |
+----+---------+-----------------+-----------+
|  1 |       1 | comment-1-1     |      NULL |
|  2 |       1 | comment-1-2     |      NULL |
|  3 |       3 | comment-3-1     |      NULL |
|  4 |       1 | comment-1-2-1   |         2 |
|  5 |       1 | comment-1-2-2   |         2 |
|  6 |       1 | comment-1-2-1-1 |         4 |
|  7 |       1 | new comment     |         6 |
+----+---------+-----------------+-----------+

※階層詳細（ポストに入ったコメント、コメントに入ったコメントの階層図）
post-1
  comment-1-1
  comment-1-2
    comment-1-2-1
      comment-1-2-1-1
        new comment
    comment-1-2-2
post-2
post-3
  comment-3-1
```
コード (id=2のコメントからそれに続くコメントを抽出)
```SQL
WITH RECURSIVE t AS (
  SELECT * FROM comments WHERE parent_id = 2 -- 最初のサブクエリが t となり1回実行する
  UNION ALL
  SELECT     -- ここから丸括弧内の最後までが、値が返ってこなくなるまで何度も繰り返す
    comments.*
  FROM
    comments JOIN t
  ON
    comments.parent_id = t.id
)
SELECT * FROM t;
```
結果
```bash
+------+---------+-----------------+-----------+
| id   | post_id | comment         | parent_id |
+------+---------+-----------------+-----------+
|    4 |       1 | comment-1-2-1   |         2 | <- 最初のサブクエリで抽出
|    5 |       1 | comment-1-2-2   |         2 | <- 最初のサブクエリで抽出
|    6 |       1 | comment-1-2-1-1 |         4 | <- 次のサブクエリで抽出
|    7 |       1 | new comment     |         6 | <- さらに繰り返したサブクエリで抽出
+------+---------+-----------------+-----------+
```

### 再起的ではないCTE（サブクエリをわかりやすく書き換えるためのもの）  
CTEを使っていないコード
```SQL
select * from comments where parent_id = 2
union all
select comments.* from comments
join (select * from comments where parent_id = 2) as t -- １行名と同じサブクエリ
on comments.parent_id = t.id;
```
CTEを使った同じ内容のコード
```SQL
with t as (select * from comments where parent_id = 2) -- サブクエリをtに置き換える
select * from t -- tを呼び出す
union all
select comments.* from comments
join t -- tを呼び出す
on comments.parent_id = t.id;
```
結果
```bash
+----+---------+-----------------+-----------+
| id | post_id | comment         | parent_id |
+----+---------+-----------------+-----------+
|  4 |       1 | comment-1-2-1   |         2 |
|  5 |       1 | comment-1-2-2   |         2 |
|  6 |       1 | comment-1-2-1-1 |         4 |
+----+---------+-----------------+-----------+
```
[重要]　`WITH`で定義したCTEは、すぐあとに続く`SELECT`文の中で使う必要がある  
つまり、`T`というCTEを定義したあとすぐに`SELECT`を書かなくてはいけない
