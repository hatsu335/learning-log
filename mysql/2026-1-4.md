## [再帰的CTE深堀り]

### 構文の仕組み

```sql
with recursive t as (
    -- ① アンカー部（初期データ）
    select * from comments where parent_id = 2

    union all

    -- ② 再帰部（前の結果を使って再帰的に広げる）
    select comments.* from comments
    join t on comments.parent_id = t.id
)
select * from t;
```

### ポイントはこの2つの `SELECT` の役割の違い

| 部分 | 役割 | 説明 |
|------|------|------|
| **① アンカー部** | 初期値 | 再帰の起点。ここで `parent_id = 2` のコメントをまず取得 |
| **② 再帰部** | 再帰的に広げる | ①や前回の結果（`t`）を使って、子コメントをたどる |

この2つを `UNION ALL` でつなぐことで、**「親 → 子 → 孫 → …」と再帰的に展開**していく

---

### 挙動の詳細

1. **最初にアンカー部が実行されて、`t` に初期データが入る**
2. **その `t` を使って再帰部が実行され、さらに `t` に追加される**
3. **新しいデータが追加されなくなるまで繰り返す**

つまり、**`t` は毎回少しずつ大きくなっていく**

---

### 実際の現場での活用シーン

### 1. **コメントのスレッド構造**
- 今回の例のように、掲示板やチャットで「親コメント → 子コメント → 孫コメント…」と続く構造をたどるときに使う

### 2. **組織図の階層**
- ある社員の上司、そのまた上司…とたどるとき
- 逆に、ある部長の配下にいる全社員を取得したいとき

### 3. **カテゴリの階層構造**
- 商品カテゴリやメニュー構造など、親子関係を持つデータの展開に

### 4. **ファイルシステムのような構造**
- フォルダとファイルのツリーを再帰的にたどるとき

---

### 注意点

- **無限ループ**  
  間違って自己参照がループしていると、無限に再帰してしまうことがある  
  → `MAXRECURSION` の制限を使うと安全（DBによって書き方が異なります）

- **パフォーマンス**  
  再帰は便利だが、深い階層や大量データでは重くなることも  
  → 必要に応じて `LIMIT` や `WHERE` 句で制限をかけるとよい

## [Trigger]

トリガーは、**特定のテーブル操作に対して自動的に実行される処理**  
トリガーは「裏でこっそり動く自動処理」みたいなもの  
業務ロジックの一部をDBに持たせたいときには便利だけだが、  
**「何が起きてるか分かりにくくなる」リスク**もあるので、**ログを残す・命名を丁寧にする・コメントをつける**ことが大事

### MySQLのTrigger

あるテーブルに対して **`INSERT` / `UPDATE` / `DELETE`** が実行されたときに、自動的に発動する処理  
たとえば、「レコードが追加されたらログを残す」「在庫が減ったら履歴を記録する」などに使える

---
### トリガーのイベント種類

MySQLでは、以下の **6種類のイベント** に対してトリガーを設定できる：

| タイミング | 操作 | イベント名（Triggerの種類） |
|------------|------|------------------------------|
| BEFORE     | INSERT | `BEFORE INSERT`             |
| AFTER      | INSERT | `AFTER INSERT`              |
| BEFORE     | UPDATE | `BEFORE UPDATE`             |
| AFTER      | UPDATE | `AFTER UPDATE`              |
| BEFORE     | DELETE | `BEFORE DELETE`             |
| AFTER      | DELETE | `AFTER DELETE`              |

---
### 使い方の基本構文

```sql
CREATE TRIGGER トリガー名
[BEFORE | AFTER] [INSERT | UPDATE | DELETE]
ON テーブル名
FOR EACH ROW
BEGIN
    -- 実行したい処理
END;
```

---

### 例：ログテーブルにINSERTされたら履歴を記録

```sql
CREATE TABLE logs (
    id INT AUTO_INCREMENT PRIMARY KEY,
    message TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE logs_history (
    id INT AUTO_INCREMENT PRIMARY KEY,
    log_id INT,
    action VARCHAR(10),
    timestamp DATETIME
);

DELIMITER $$

CREATE TRIGGER log_insert_trigger
AFTER INSERT ON logs
FOR EACH ROW
BEGIN
    INSERT INTO logs_history (log_id, action, timestamp)
    VALUES (NEW.id, 'insert', NOW());
END$$

DELIMITER ;
```

### TRIGGERの内容確認
```bash
show trigger\G
```
バックスラッシュの後の`G`は大文字にする

### 解説：
- `AFTER INSERT`：`logs` テーブルに新しい行が追加された後に発動
- `NEW.id`：挿入されたレコードの `id` を参照
- `logs_history` に履歴を記録

---

### `NEW` と `OLD` の使い分け

| コンテキスト | 使用できる変数 |
|--------------|----------------|
| `INSERT`     | `NEW.カラム名` |
| `UPDATE`     | `NEW.カラム名`, `OLD.カラム名` |
| `DELETE`     | `OLD.カラム名` |

---

### 実務での活用シーン

- **監査ログの記録**（更新・削除の履歴を残す）
- **在庫の自動調整**（注文が入ったら在庫を減らす）
- **関連テーブルの自動更新**（削除時に子テーブルも削除など）
- **データの整形・補完**（入力値の正規化や自動補完）

---

### 注意点

- トリガーは**自動で実行されるため、見えにくくデバッグしづらい**です
- **複雑なロジックはアプリケーション側で処理する方が保守性が高い**ことも
- **トリガーの中で別のトリガーが発動する**と、無限ループになる危険もあるので注意

## [DELIMITER]

`DELIMITER $$` と `DELIMITER ;` は、MySQLクライアントで  
複数行のSQL文（特にストアドプロシージャやトリガー）を書くときに必要な構文

---

## なぜ `DELIMITER` が必要なのか

通常、MySQLでは `;` が「SQL文の終わり」を意味する  
トリガーやストアドプロシージャの中では `;` をたくさん使うので、途中で文が終わったと誤解されてしまう

---

## 例

```sql
DELIMITER $$

CREATE TRIGGER log_insert_trigger
AFTER INSERT ON logs
FOR EACH ROW
BEGIN
    INSERT INTO logs_history (log_id, action, timestamp)
    VALUES (NEW.id, 'insert', NOW());
END$$

DELIMITER ;
```

### 何が起きてるか

1. `DELIMITER $$`  
   → 通常の `;` の代わりに `$$` を「文の終わり」として使うように変更

2. `... END$$`  
   → トリガー定義の終わりを `$$` で明示

3. `DELIMITER ;`  
   → 元の状態（`;`が区切り）に戻す

---

## まとめ

イメージは、「この間だけ特別ルールで」と宣言して、終わったら「元に戻す」と言ってるような感じ  
トリガーやプロシージャの中では `;` を普通に使いたいから、外側の区切り記号を一時的に変えている  
MySQL Workbench などのGUIツールでは、`DELIMITER` を自動で処理してくれることが多い  
しかし、コマンドライン（mysqlクライアント）では必須  

## [Markdown記法]

### 引用文表現

記入方法
```text
> つまりインスタンスもオブジェクトである。
```
結果  
> つまりインスタンスもオブジェクトである。

---

### 強調する

記入方法
```text
すこし強調して*斜体*にする場合と、もっと強く強調する**太字**がある。
```
結果  
すこし強調して*斜体*にする場合と、もっと強く強調する**太字**がある。

---

### リストの表現

記入方法
```text
- アメリカ
- インド
- 日本
  - 東京
  - 名古屋

1. 人口        <- 先頭はすべて「1.」でOK。自動で連番になる
1. 気候           後から途中に項目を追加しても良い仕組み
1. 治安
   1. 重犯罪率
   1. 軽犯罪率
```
結果  
- アメリカ
- インド
- 日本
  - 東京
  - 名古屋

1. 人口
1. 気候
1. 治安
   1. 重犯罪率
   1. 軽犯罪率

---

### リンク集

記入方法
```text
- http://yahoo.co.jp            <- アドレスはそのままリンクになる
- [ヤフー](http://yahoo.co.jp)   <- 文字にリンクを貼る場合は [文字列](サイトアドレス) となる
```
結果  
- http://yahoo.co.jp
- [ヤフー](http://yahoo.co.jp)

---

### 画像貼り付け

記入方法
```text
![愛知県図書館](https://www.aichi-pref-library.jp/core/img/logo.png)

  構文: ![画像説明](画像アドレス)


[![愛知県図書館](https://www.aichi-pref-library.jp/core/img/logo.png)](https://www.aichi-pref-library.jp/)

  構文: [![画像説明](画像アドレス)](サイトアドレス)
```
結果  
![愛知県図書館](https://www.aichi-pref-library.jp/core/img/logo.png)

[![愛知県図書館](https://www.aichi-pref-library.jp/core/img/logo.png)](https://www.aichi-pref-library.jp/)

**解説**  
上段は画像のみで、下段は画像にリンクを貼っている。  
対象画像に対して右クリックして「画像アドレスをコピー」でアドレスを取得する  
自分のPC内の画像を使用する場合はMarkdown文書からの相対パスを使用する  
Markdown文書と画像が同じ階層にある場合は`![abc.md](abc.jpg)`となる
