## [マテリアライズドビュー]

### マテリアライズドビューとは通常のビューとは異なり、クエリ結果を物理的にテーブルとして保存するしくみ  
- MySQLでは「マテリアライズドビュー」という機能が正式には存在しない  
- それに近い仕組みを自分で構築することはできる  


### 通常のビューとの違い

| 特徴 | 通常のビュー | マテリアライズドビュー |
|------|--------------|------------------------|
| 実体 | 実体を持たない（仮想） | 実体を持つ（物理テーブル） |
| データの更新 | 元テーブルの変更が即時反映 | 手動またはスケジュールで更新 |
| パフォーマンス | クエリ実行時に毎回再計算 | 事前に計算済みなので高速 |
| 更新コスト | なし | 更新処理が必要（全更新 or 差分更新） |

---

### MySQLでのマテリアライズドビュー的な実装方法  
MySQLには `CREATE MATERIALIZED VIEW` のような文法はないけれど  
**定期的に更新される集計テーブル**を作ることで、同様の効果を得られる  

### 方法①：全更新（フルリフレッシュ）

1. **集計用のテーブルを作成**
   ```sql
   CREATE TABLE sales_summary AS
   SELECT customer_id, SUM(amount) AS total
   FROM sales
   GROUP BY customer_id;
   ```

2. **定期的に全削除＆再挿入**
   ```sql
   DELETE FROM sales_summary;

   INSERT INTO sales_summary
   SELECT customer_id, SUM(amount)
   FROM sales
   GROUP BY customer_id;
   ```

3. **スケジューラで自動化**
   - `cron` や MySQLの `EVENT` 機能を使って定期実行

---

### 方法②：差分更新（インクリメンタルリフレッシュ）

1. **更新対象を特定するための仕組みが必要**
   - `sales` テーブルに `updated_at` や `last_modified` カラムがあると便利

2. **変更分だけを抽出して更新**
   ```sql
   INSERT INTO sales_summary (customer_id, total)
   SELECT customer_id, SUM(amount)
   FROM sales
   WHERE updated_at > (SELECT last_refresh_time FROM refresh_log)
   GROUP BY customer_id
   ON DUPLICATE KEY UPDATE total = VALUES(total);
   ```

3. **更新ログを管理**
   - `refresh_log` テーブルなどを用意して、前回更新時刻を記録

---

### どちらを選ぶべきか

| 条件 | おすすめの方法 |
|------|----------------|
| データ量が少ない or 更新頻度が低い | フルリフレッシュ |
| データ量が多い or 更新頻度が高い | 差分更新（インクリメンタル） |


「見積書の集計」や「月次レポート」みたいな処理があるなら、マテリアライズドビュー的なテーブルを使うと**パフォーマンスも安定して、帳票出力もスムーズ**になる  


---

### 具体例：売上集計テーブルをマテリアライズドビュー的に運用する

### 前提：元データのテーブル `sales`

```sql
CREATE TABLE sales (
    id INT AUTO_INCREMENT PRIMARY KEY,
    customer_id INT,
    amount DECIMAL(10,2),
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

このテーブルには、売上データが入っていて、`updated_at` で更新日時を記録してる

---

### ステップ①：集計用テーブル（マテリアライズドビュー）を作成

```sql
CREATE TABLE sales_summary (
    customer_id INT PRIMARY KEY,
    total_amount DECIMAL(10,2),
    last_updated DATETIME
);
```

---

### ステップ②：初回のフルリフレッシュ

```sql
INSERT INTO sales_summary (customer_id, total_amount, last_updated)
SELECT customer_id, SUM(amount), MAX(updated_at)
FROM sales
GROUP BY customer_id;
```

---

### ステップ③：差分更新（インクリメンタルリフレッシュ）

```sql
-- 変更のあった customer_id を抽出
WITH changed AS (
    SELECT customer_id, SUM(amount) AS total, MAX(updated_at) AS last_updated
    FROM sales
    WHERE updated_at > (SELECT MAX(last_updated) FROM sales_summary)
    GROUP BY customer_id
)
-- 既存の summary テーブルにマージ
INSERT INTO sales_summary (customer_id, total_amount, last_updated)
SELECT customer_id, total, last_updated FROM changed
ON DUPLICATE KEY UPDATE
    total_amount = VALUES(total_amount),
    last_updated = VALUES(last_updated);
```

これで、更新のあった顧客だけを効率よく反映できる

---

### Pythonやバッチ処理と組み合わせた運用方法

MySQL単体でも `EVENT` を使って定期実行できるが、**Pythonで制御するともっと柔軟に運用できる**

### Pythonスクリプト例（差分更新）

```python
import mysql.connector
from datetime import datetime

conn = mysql.connector.connect(
    host='localhost',
    user='your_user',
    password='your_pass',
    database='your_db'
)
cursor = conn.cursor()

# 差分更新のSQLを実行
update_sql = """
WITH changed AS (
    SELECT customer_id, SUM(amount) AS total, MAX(updated_at) AS last_updated
    FROM sales
    WHERE updated_at > (SELECT MAX(last_updated) FROM sales_summary)
    GROUP BY customer_id
)
INSERT INTO sales_summary (customer_id, total_amount, last_updated)
SELECT customer_id, total, last_updated FROM changed
ON DUPLICATE KEY UPDATE
    total_amount = VALUES(total_amount),
    last_updated = VALUES(last_updated);
"""

cursor.execute(update_sql)
conn.commit()
cursor.close()
conn.close()
```

### 実行方法

- Windowsなら `.bat` ファイルを作ってタスクスケジューラで定期実行
- Linuxなら `cron` で定期実行

---

### どんなときに使うといいか

- 複雑なJOINや集計を含むビューを**高速に参照したいとき**
- 帳票出力やAPIレスポンスに**即時性と安定性**が求められるとき
- データ量が多く、**リアルタイム集計が重いとき**

## [外部キー制約の参照]

### テーブル削除したいときなど

```sql
SELECT
  TABLE_NAME,
  COLUMN_NAME,
  CONSTRAINT_NAME,
  referenced_table_name,
  referenced_column_name
FROM information_schema.KEY_COLUMN_USAGE
WHERE `REFERENCED_TABLE_NAME` = 'posts'
AND `TABLE_SCHEMA` = 'my_schema';
```
結果
```bash
+------------+-------------+-----------------+-----------------------+------------------------+
| TABLE_NAME | COLUMN_NAME | CONSTRAINT_NAME | REFERENCED_TABLE_NAME | REFERENCED_COLUMN_NAME |
+------------+-------------+-----------------+-----------------------+------------------------+
| comments   | post_id     | comments_ibfk_1 | posts                 | id                     |
+------------+-------------+-----------------+-----------------------+------------------------+
```

結果からは`comments`テーブルから`post_id`を参照していることが分かる  

---

### VSCODEサイドバーからの確認  
`VSCODE`サイドバーからテーブル名を右クリックして`SHOW TABLE DDL`で確認すると  
`FOREIGN KEY ()`の部分が外部キー制約を指している  

表示された例
```SQL
CREATE TABLE `comments` (
  `id` int NOT NULL AUTO_INCREMENT,
  `post_id` int DEFAULT NULL,
  `comment` varchar(140) DEFAULT NULL,
  `parent_id` int unsigned DEFAULT NULL,
  PRIMARY KEY (`id`),
  KEY `post_id` (`post_id`),
  CONSTRAINT `comments_ibfk_1` FOREIGN KEY (`post_id`) REFERENCES `posts` (`id`) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB AUTO_INCREMENT=8 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci
```

## [ローカルファイルの読み込み許可]

### MySQLの実行ファイルのパスを通す

**WindowsのPowerShellやコマンドプロンプトで `mysql` コマンドが認識されていない**状態だったため  
実行ファイルのパスを通す必要が発生  

#### ステップ①：MySQLのインストール場所を確認

通常、MySQLは以下のような場所にインストールされていることが多い

```
C:\Program Files\MySQL\MySQL Server 8.0\bin
```

この中に `mysql.exe` がある

---

#### ステップ②：一時的にパスを通して実行する方法（今回見送り）

PowerShellやコマンドプロンプトで、次のように**フルパスで実行**する

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u your_user -p --local-infile=1
```

（`your_user` は自分のユーザー名に置き換える）

---

#### ステップ③：恒久的にパスを通す方法（こちらに決定）

1. **Windowsキー →「環境変数」と検索 →「システム環境変数の編集」**
2. 「環境変数(N)...」をクリック
3. 「システム環境変数」または「ユーザー環境変数」の中の `Path` を選択して「編集」
4. 「新規」→ `C:\Program Files\MySQL\MySQL Server 8.0\bin` を追加
5. OKを押してすべて閉じる

---

### クライアント側の読み込み許可

#### ① まず、MySQLから**一度抜ける**

```sql
mysql> exit
Bye
```

#### ② そのあと、**ターミナルやコマンドプロンプトで**以下を実行：

```bash
mysql -u your_user -p --local-infile=1
```

（`your_user` の部分は自分のユーザー名に置き換え）

パスワードを聞かれたら入力してログイン後、以下のコードで設定を確認

```sql
mysql> SHOW VARIABLES LIKE 'local_infile';
```

これで `ON` になっていれば良いが、サーバー側が`OFF`になっていると  
クライアント側も`OFF`で表示されてしまう  
つまり、クライアント側では `local-infile=1` が有効になっているけど、  
サーバー側で無効になっているということ  

---

### サーバー側の読み込み許可

設定を確認・変更する方法

### ① サーバー側の `local_infile` を確認

```sql
SHOW GLOBAL VARIABLES LIKE 'local_infile';
```

これで `Value` が `OFF` なら、**サーバー側で無効になってる**ということ

---

### ② サーバー側で `local_infile` を有効にする方法

#### 方法A：設定ファイルに追記（恒久的）**(今回は見送り)**

MySQLの設定ファイル（`my.ini` または `my.cnf`）を開いて、以下を追加：

```ini
[mysqld]
local_infile=1
```

その後、MySQLサーバーを再起動：

```powershell
net stop mysql
net start mysql
```

---

#### 方法B：一時的に有効にする（再起動でリセットされる）**(今回はこちらを選択)**

MySQL CLI から入力
```sql
SET GLOBAL local_infile = 1;
```

---

### 補足：`--local-infile=1` は「クライアント側の許可」

- `--local-infile=1` は「**クライアントがローカルファイルを送ってもいいよ**」という設定
- 一方、`local_infile` 変数は「**サーバーがそれを受け入れるかどうか**」の設定

つまり、**両方がOKじゃないと `LOAD DATA LOCAL INFILE` は使えない**

---

### まとめ

| 設定場所 | 目的 | 設定方法 |
|----------|------|----------|
| クライアント | ローカルファイルの送信許可 | `--local-infile=1` |
| サーバー | ローカルファイルの受信許可 | `local_infile=1` を設定ファイルに追加 or `SET GLOBAL` |

---

## 重要なウンチク

### 1. 一時的に有効にする方法は、PC再起動とDB再起動のどちらでリセットされるか

答えは：**MySQLサーバーの再起動でリセットされる**

```sql
SET GLOBAL local_infile = 1;
```

このコマンドで有効にした設定は、**メモリ上に一時的に反映されるだけ**  

| 状況 | `local_infile` の状態 |
|------|------------------------|
| MySQLサーバーを再起動 | **OFFに戻る**（設定が消える） |
| PCを再起動（＝MySQLも再起動） | **OFFに戻る** |
| クライアントを再起動 | **影響なし**（サーバー側の設定は維持） |

恒久的にONにしたい場合は `my.ini` に書くのが確実

---

### 2. `local_infile` を ON にするのはセキュリティ的に望ましくないのか

### **重要ポイント**

#### セキュリティ的な懸念

- `LOAD DATA LOCAL INFILE` は、**クライアントのローカルファイルをサーバーに送信して読み込ませる**機能
- もし悪意のあるユーザーがいたら、**意図しないファイルを読み込ませて情報を盗む**ことも理論上は可能

たとえば：

```sql
LOAD DATA LOCAL INFILE '/etc/passwd' INTO TABLE users;
```

↑ こんなことができてしまうと大問題

#### だから、**デフォルトでは OFF**

MySQL 8.0 以降では、セキュリティ強化のために `local_infile` は **デフォルトで OFF** になってる

---

### 3. Pythonなどから読み込むのが常識的なのか

**最近の開発現場では Python やアプリケーションコードからデータを読み込んで挿入するのが一般的**

### なぜかというと：

- **セキュリティが高い**（ファイルの読み込み元をアプリ側で制御できる）
- **柔軟な前処理ができる**（バリデーション、変換、ログ出力など）
- **データベースの設定に依存しない**（`local_infile` を気にしなくていい）

たとえば、CSVを読み込んで、必要な行だけ挿入したり、重複チェックしたり、エラーをログに残したり…  
そういう処理は `LOAD DATA` よりも **Pythonの方が圧倒的に柔軟**

---

### まとめ

| 質問 | 答え |
|------|------|
| 一時的な `SET GLOBAL` はいつ消える？ | **MySQLサーバーの再起動でリセットされる** |
| `local_infile` を ON にするのは安全？ | **セキュリティ上のリスクがあるため、デフォルトで OFF** |
| Pythonで読み込むのが常識？ | **はい。柔軟性・安全性の面で主流になっている** |


## [外部ファイルからのデータ読み込み]

テーブル
```sql
CREATE TABLE posts_input_file (
  id      INT NOT NULL AUTO_INCREMENT,
  message VARCHAR(140),
  likes   INT UNSIGNED,
  area    VARCHAR(20),
  PRIMARY KEY(id)
);
```

ファイル読み込みコード
```sql
LOAD DATA LOCAL INFILE 'D:/MySQL_sakila/data.csv' INTO TABLE posts_input_file
  FIELDS TERMINATED BY ','
  LINES TERMINATED BY '\n'
  IGNORE 1 LINES
  (message, likes, area);
```
- ファイル指定は絶対パスにした方が扱いやすい(相対パスは階層が深く、そこにファイルを置くのはイヤ)
- ファイルに右クリックでパスを取得すると`\(バックスペース)`になっているので`/`に変更すると良い

読み込んだCSV(5行抜粋)
```csv
message,likes,area
post-1,136,Tokyo
post-2,27,Osaka
post-3,125,Osaka
post-4,40,Kanazawa
post-5,19,Wakayama
...
```

#### CSVファイルの情報を指定

`FIELDS TERMINATED BY ','`値の区切りは`,`を使用

`LINES TERMINATED BY '\n'`行の改行に`\n`を使用

`IGNORE 1 LINES`は先頭の1行を飛ばす
