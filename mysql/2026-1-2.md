## [GitHubリポジトリ作成]

### ステップ1：GitHubで新しいリポジトリを作成

1. GitHubにログイン
2. 右上の「＋」→「New repository」をクリック
3. リポジトリ名を入力（例：`ml-projects`）
4. 「Public」か「Private」を選択
5. 「Initialize this repository with a README」はチェックしない（ローカルに既にコードがあるので）
6. 「Create repository」をクリック

### ステップ2：ローカルでGitリポジトリを初期化

ターミナル（またはコマンドプロンプト）を開いて、コードがあるディレクトリに移動：

```bash
cd /path/to/your/ml-project
```

Gitリポジトリを初期化：

```bash
git init
```

### ステップ3：ファイルをステージングしてコミット

まず、`.gitignore` ファイルを作成して、追跡したくないファイル（例：`__pycache__` や `.ipynb_checkpoints/`、`*.pyc`、`*.log`、`venv/` など）を除外しておく。

ファイルをステージング：

```bash
git add .
```

コミット：

```bash
git commit -m "Initial commit: Add machine learning project"
```

### ステップ4：GitHubリポジトリと接続してpush

GitHubで作成したリポジトリのURLをコピーして、以下のようにリモートを追加：

```bash
git remote add origin https://github.com/ユーザー名/ml-projects.git
```

現在のプロジェクトがとのリモートとつながっているか確認：

```bash
git remote -v
```

初回push（`main` ブランチにpushする場合）：

```bash
git branch -M main
git push -u origin main
```

---
GitHubにアクセスして、コードが反映されているか確認

### Initialize this repository with a README とは  

「Initialize this repository with a README」というのは、GitHub上でリポジトリを作成するときに、最初からREADMEファイルを1つ入れておきますか？という意味


### チェックを入れるとどうなる？

- GitHubが自動で `README.md` を作ってくれる
- リポジトリが初期化（initialize）されて、`main` ブランチができる
- 最初のコミットが作られる

### チェックを入れない方がいい場合  
すでにローカルにコードがあって、それをGitHubにアップロードしたいときは、チェックを入れない方がいい  
GitHub側に先にファイルがあると、ローカルと競合してしまって、pushするときにエラーになることがある

### まとめ

| 状況 | 「Initialize with a README」のチェック |
|------|----------------------------------------|
| GitHub上で最初から作業を始める | ✅ 入れる |
| ローカルに既にコードがある | ❌ 入れない（今回のケース！） |


READMEを後から追加したくなったら、ローカルで `README.md` を作って、普通に `git add` → `commit` → `push` すればOK！

## [GitHubコメント変更]

### 直前のコミットメッセージを変更するには？

```bash
git commit --amend
```

エディタ（たとえばVS Codeやvim）が開いて、前のメッセージが表示される  

### 注意点！

すでにリモートに push 済みのコミットを amend すると履歴が書き換わるため、  
他の人と共有しているリポジトリではコンフリクトの原因になることがある  
その場合は、`--force`（または `--force-with-lease`）で push し直す必要がある

```bash
git push --force-with-lease
```

### 複数の過去のコミットを直したいときは？

 `git rebase -i`（インタラクティブ・リベース）を使う

```bash
git rebase -i HEAD~3
```

→ 直近3件のコミットを一覧で編集できる。  
`pick` を `reword` に変えると、コメントだけ書き換えられる

### まとめ

| やりたいこと | コマンド | 備考 |
|--------------|----------|------|
| 直前のコミットメッセージを修正 | `git commit --amend` | ローカルでの修正に最適 |
| 複数の過去のメッセージを修正 | `git rebase -i HEAD~N` | `reword` を使う |
| 修正後にリモートへ反映 | `git push --force-with-lease` | 注意して使おう！ |

## ※Vimの基本操作

### Vimには「モード」がある！

| モード | 説明 |
|--------|------|
| ノーマルモード | コマンドを入力するモード（起動時はこれ） |
| 挿入モード | 文字を入力・編集できるモード |
| コマンドモード | `:` から始まるコマンドを入力するモード（保存・終了など） |

### 編集の流れ（コミットメッセージを修正する場合）

### 1. 挿入モードに入る

起動直後はノーマルモードなので、まずは編集できるように：

```bash
i
```

→ 画面の左下に `-- INSERT --` と出たらOK！  
これで普通に文字が打てるようになる

### 2. メッセージを編集する

- 普通にキーボードで文字を打てばOK！
- バックスペースや矢印キーも使える

### 3. 編集が終わったら保存して終了

1. `Esc` を押してノーマルモードに戻る（`-- INSERT --` が消える）
2. コマンドモードに入るために `:` を押す
3. 次のように入力して保存＆終了：

```bash
:wq
```

4. `Enter` を押す！

### まとめ：よく使うVim操作

| 操作 | キー入力 | 説明 |
|------|----------|------|
| 編集を始める | `i` | 挿入モードに入る |
| 保存して終了 | `Esc` → `:wq` → `Enter` | 編集を確定して終了 |
| 終了だけ（保存しない） | `Esc` → `:q!` → `Enter` | 編集を破棄して終了 |
| 保存だけ（終了しない） | `Esc` → `:w` → `Enter` | 上書き保存 |

## [MySQL外部キー制約]
### 1. FOREIGN KEY(カラム名) REFERENCES テーブル名(カラム名)  

例：FOREIGN KEY (post_id) REFERENCES posts(id)

1.`commentsテーブル`の`post_id`には`postsテーブル`の`id`に  
無い値が挿入されようとするとエラーを返す  

2.`commentsテーブル`は`postsテーブル`の`id`を常に参照している  
ので`commentsテーブル`が存在している限り`postsテーブル`を削除  
することはできない。（整合性が失われるため）
```SQL
CREATE TABLE posts (
  id INT NOT NULL AUTO_INCREMENT,
  message VARCHAR(140),
  PRIMARY KEY (id)
);

CREATE TABLE comments (
  id INT NOT NULL AUTO_INCREMENT,
  post_id INT,
  comment VARCHAR(140),
  PRIMARY KEY (id),
  FOREIGN KEY (post_id) REFERENCES posts(id) -- 外部キー制約
);

INSERT INTO posts (message) VALUES
  ('post-1'),
  ('post-2'),
  ('post-3');

INSERT INTO comments (post_id, comment) VALUES
  (1, 'comment-1-1'),
  (1, 'comment-1-2'),
  (3, 'comment-3-1');
  (4, 'comment-4-1'); -- この値がエラーになる
```

### 2. ON DELETE CASCADE  
`posts(id)`に紐づいた値も同時に削除される（下記コード参照）  

例：`posts(id)`の 3 を消すと、`comments(post_id)`が 3 の値が削除される  

### 3. ON UPDATE CASCADE  
`posts(id)`に紐づいた値も同時に更新される（下記コード参照）  

例：`posts(id)`の 3 を 100 にすると、`comments(post_id)`が 3 が 100 に更新される  

上記の２つのコードを`commentsテーブル`に追加して変更
```sql
CREATE TABLE comments (
  id INT NOT NULL AUTO_INCREMENT,
  post_id INT,
  comment VARCHAR(140),
  PRIMARY KEY (id),
  FOREIGN KEY (post_id) REFERENCES posts(id)
    ON DELETE CASCADE -- 追加分
    ON UPDATE CASCADE -- 追加分
);
```

## [LAST_INSERT_ID()]

### 直前の挿入の結果として`AUTO_INCREMENT`で生成された最初の`id`を取得する  

（「最初の」とついているのは、一度に複数の行を挿入した場合にはそのうち最初の`id`が対象になるという意味）  
`id`の値を指定して`INSERT`を行うと`AUTO_INCREMENT`による`id`の生成が行われないため`LAST_INSERT_ID()`の対象とならない  

```SQL
INSERT INTO comments (post_id, comment) VALUES
  (LAST_INSERT_ID(), 'new omment');
```

## [DELLノートパソコンのネットワークセッティング]
### Windows Server をインストールする前準備  

過去に経験の無い問題発生。結論からいうと、IPv4のプロファイルが壊れていた。  
以下が追及するまでに使用したコマンド  

ルーターのIPアドレスをチェック（デフォルトゲートウェイ）
```bash
ipconfig
```

PC名でアクセスできるかチェック
```bash
\\相手のPC名
```

IPアドレスでアクセスできるかチェック
```bash
\\IPアドレス
```

ネットワークのプロファイルの確認
```bash
Get-NetConnectionProfile
```

**調査結果**  
ネットワークのプロファイルを確認したところ`Name`が「識別されていないネットワーク」と表示  
され、`NetworkCategory`が「Public」になっていた。さらに`IPv4Connectivity`が「Internet」  
になっていなかった。  

**原因**  
上記のことから、今までインターネットが使えていたのはIPv6のおかげで、IPv4のプロファイルは  
壊れていた。そのせいで名前が識別されず、さらにPublicになっていた。

**対処**  
Wi-Fiを別回線に切り替えたところすべてうまくいった。仮に別回線が無い場合はプロファイルを  
消してしまって再起動すると再インストールされるので直るかもしれない、もしくはネットワーク  
のリセットやWi-Fiの再接続なども可能性がある。
