### 一番借りているジャンルを特定し、指標に加えランク付けを追加

```sql
WITH genre_rental AS (
SELECT
  ct.customer_id AS ct_id,
  ct.first_name AS f_name,
  ct.last_name AS l_name,
  c.name AS genre,
  COUNT(ct.customer_id) AS genre_rentals
FROM customer ct
JOIN rental r ON ct.customer_id = r.customer_id
JOIN inventory i ON r.inventory_id = i.inventory_id
JOIN film_category fc ON i.film_id = fc.film_id
JOIN category c ON fc.category_id = c.category_id
GROUP BY ct.customer_id, c.name
), analysis_summary AS (
SELECT
  *,
  SUM(genre_rentals) OVER (PARTITION BY ct_id) AS rentals,
  COUNT(genre_rentals) OVER (PARTITION BY ct_id) AS genres,
  ROW_NUMBER() OVER (PARTITION BY ct_id ORDER BY genre_rentals DESC) AS genre_rank
FROM genre_rental
)
SELECT
  ct_id,
  f_name,
  l_name,
  genre,
  genre_rentals AS g_rentals,
  rentals,
  genres,
  ROUND(genre_rentals / rentals * 100, 1) AS preference,
  ROUND(rentals / genres, 2) AS density,
  CASE 
    WHEN genre_rentals / rentals * 100 > 27.0 THEN 'A'
    WHEN genre_rentals / rentals * 100 > 23.5 THEN 'B'
    WHEN genre_rentals / rentals * 100 > 20.0 THEN 'C' 
    ELSE '-' 
  END AS target_rank
FROM analysis_summary
WHERE genre_rank = 1
ORDER BY density DESC;
```

### 月別売上推移

スタッフ別、月別売上一覧
```sql
SELECT
  staff_id AS staff,
  SUM(CASE WHEN DATE_FORMAT(payment_date, '%Y-%m') = '2005-05' THEN amount ELSE 0 END) AS '2005-05',
  SUM(CASE WHEN DATE_FORMAT(payment_date, '%Y-%m') = '2005-06' THEN amount ELSE 0 END) AS '2005-06',
  SUM(CASE WHEN DATE_FORMAT(payment_date, '%Y-%m') = '2005-07' THEN amount ELSE 0 END) AS '2005-07',
  SUM(CASE WHEN DATE_FORMAT(payment_date, '%Y-%m') = '2005-08' THEN amount ELSE 0 END) AS '2005-08'
FROM payment
GROUP BY staff_id;
```
結果
```bash
+-------+---------+---------+----------+----------+
| staff | 2005-05 | 2005-06 | 2005-07  | 2005-08  |
+-------+---------+---------+----------+----------+
|     1 | 2621.83 | 4774.37 | 13998.56 | 11853.65 |
|     2 | 2201.61 | 4855.52 | 14370.35 | 12216.49 |
+-------+---------+---------+----------+----------+
```

**改善点**  
`DATE_FORMAT`で出力された値は`datetime型`では無く`varchar型`になる  
しかし`YEAR()`や`MONTH()`で出力された値は`int型`になるためインデックスが効きやすい  
よってデータが巨大になるほどこのあたりの扱いに注意が必要となる

店舗別、月別売上一覧
```sql
SELECT
  s.store_id AS store,
  SUM(CASE WHEN YEAR(p.payment_date) = 2005 AND MONTH(p.payment_date) = 5 THEN p.amount ELSE 0 END) AS '2005-05',
  SUM(CASE WHEN YEAR(p.payment_date) = 2005 AND MONTH(p.payment_date) = 6 THEN p.amount ELSE 0 END) AS '2005-06',
  SUM(CASE WHEN YEAR(p.payment_date) = 2005 AND MONTH(p.payment_date) = 7 THEN p.amount ELSE 0 END) AS '2005-07',
  SUM(CASE WHEN YEAR(p.payment_date) = 2005 AND MONTH(p.payment_date) = 8 THEN p.amount ELSE 0 END) AS '2005-08'

```

縦持ち、店舗別、月別売上一覧
```sql
SELECT
  s.store_id AS store,
  DATE_FORMAT(p.payment_date, '%Y-%m') AS monthly,
  SUM(p.amount) AS sales
FROM payment p
JOIN staff s ON p.staff_id = s.staff_id
GROUP BY s.store_id, monthly
ORDER BY monthly;
```
結果
```bash
+-------+---------+----------+
| store | monthly | sales    |
+-------+---------+----------+
|     1 | 2005-05 |  2621.83 |
|     2 | 2005-05 |  2201.61 |
|     1 | 2005-06 |  4774.37 |
|     2 | 2005-06 |  4855.52 |
|     1 | 2005-07 | 13998.56 |
|     2 | 2005-07 | 14370.35 |
|     1 | 2005-08 | 11853.65 |
|     2 | 2005-08 | 12216.49 |
|     1 | 2006-02 |   234.09 |
|     2 | 2006-02 |   280.09 |
+-------+---------+----------+
```
**改善点**
`DATE_FORMAT()`より`YEAR()`や`MONTH()`を使って分ける（パフォーマンス重視の場合）  

改善してみたコード
```SQL
SELECT
  s.store_id AS store,
  CONCAT(YEAR(p.payment_date), '-', MONTH(p.payment_date)) AS monthly,
  SUM(p.amount) AS sales
FROM payment p
JOIN staff s ON p.staff_id = s.staff_id
GROUP BY s.store_id, monthly
ORDER BY monthly;
```

**改善点と問題点**  
一見改善したかのように見えるが`GROUP BY` に `CONCAT(...)` を使うとインデックスが効きにくくなる  
- `GROUP BY s.store_id, monthly` の `monthly` は `CONCAT(...)` の別名
- SQLの評価順的に、`GROUP BY` ではエイリアスは使えない（MySQLは許容するけど
- さらに、`CONCAT()` 自体が関数なので、インデックスが効かない


よりパフォーマンスを意識した改善コード
```sql
SELECT
  s.store_id AS store,
  YEAR(p.payment_date) AS year,
  MONTH(p.payment_date) AS month,
  SUM(p.amount) AS sales
FROM payment p
JOIN staff s ON p.staff_id = s.staff_id
GROUP BY s.store_id, YEAR(p.payment_date), MONTH(p.payment_date)
ORDER BY year, month;
```

**メリット**  
- `GROUP BY` に関数を使っても、`YEAR()` と `MONTH()` は単純関数なのでインデックスが効きやすい  
- `CONCAT()` を使わないことで、ソートやグループ化の負荷が軽減  
- 表示はアプリ側で `"2005-05"` に整形すればOK  

**まとめ**  
| 書き方 | パフォーマンス | コメント |
|--------|----------------|----------|
| `CONCAT(YEAR, MONTH)` | やや重い | インデックスが効きにくい可能性あり |
| `YEAR(...) AS year, MONTH(...) AS month` | 軽い | インデックスが効きやすく、拡張性も高い |
