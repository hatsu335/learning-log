## [MySQLで外部キー（FOREIGN KEY）制約を確認する方法]
以下は代表的な方法と実行例です。

### [1. SHOW CREATE TABLE で確認]
テーブル作成時のDDL（CREATE文）を表示し、外部キー定義を確認できます。
```Sql
SHOW CREATE TABLE your_table_name\G
```

例:
```Sql
SHOW CREATE TABLE orders\G
```

出力例（抜粋）:
```Sql
CONSTRAINT `orders_ibfk_1` FOREIGN KEY (`customer_id`) REFERENCES `customers` (`id`)
```

---

### [2. INFORMATION_SCHEMA.KEY_COLUMN_USAGE を使う]
外部キーの参照元・参照先を一覧で取得できます。
```Sql
SELECT 
    TABLE_NAME,
    COLUMN_NAME,
    CONSTRAINT_NAME,
    REFERENCED_TABLE_NAME,
    REFERENCED_COLUMN_NAME
FROM INFORMATION_SCHEMA.KEY_COLUMN_USAGE
WHERE TABLE_SCHEMA = 'your_database_name'
  AND REFERENCED_TABLE_NAME IS NOT NULL;
```

ポイント

TABLE_SCHEMA にデータベース名を指定
REFERENCED_TABLE_NAME IS NOT NULL で外部キーのみ抽出

---

### [3. INFORMATION_SCHEMA.TABLE_CONSTRAINTS で制約種別を確認]
外部キー制約の名前や種類を確認できます。
```Sql
SELECT 
    TABLE_NAME,
    CONSTRAINT_NAME,
    CONSTRAINT_TYPE
FROM INFORMATION_SCHEMA.TABLE_CONSTRAINTS
WHERE TABLE_SCHEMA = 'your_database_name'
  AND CONSTRAINT_TYPE = 'FOREIGN KEY';
```

---

### [4. MySQL Workbench などGUIツールで確認]
GUIツールを使えば、テーブルの外部キー関係をER図形式で視覚的に確認できます。

## [整合性のチェック]

products と orders の二次加工情報が一致しているかどうかは、SQL で簡単に検証できます。

あなたの状況を整理すると：

- **products.secondary_process** → 1 / 0（真偽値に変換予定）
- **orders.secondary_type_id** → 1 / 0（すでに真偽値）

つまり、両者は **同じ意味の値**を持つべきです。

---

### 1. 整合性チェック（不一致データを抽出）

products と orders を JOIN して、  
二次加工の値が一致しない行だけを抽出します。

```sql
SELECT 
    o.id AS order_id,
    o.product_id,
    p.secondary_process AS product_secondary,
    o.secondary_type_id AS order_secondary
FROM orders o
JOIN products p
    ON o.product_id = p.product_code
WHERE p.secondary_process <> o.secondary_type_id;
```

### このクエリでわかること
- products と orders の二次加工が **一致していない行だけ**が表示される  
- 一致していれば結果は 0 行  
- 不一致があれば、どの注文が問題かすぐにわかる

---

### 2. 一致しているかどうかの件数チェック

```sql
SELECT 
    SUM(p.secondary_process = o.secondary_type_id) AS match_count,
    SUM(p.secondary_process <> o.secondary_type_id) AS mismatch_count
FROM orders o
JOIN products p
    ON o.product_id = p.product_code;
```

### これで全体の整合性が一目でわかる  
- match_count → 一致している件数  
- mismatch_count → 不一致の件数  

---

### 3. 不一致があった場合の修正方法

もし products 側を正とするなら：

```sql
UPDATE orders o
JOIN products p ON o.product_id = p.product_code
SET o.secondary_type_id = p.secondary_process
WHERE o.secondary_type_id <> p.secondary_process;
```

逆に orders 側を正とするなら：

```sql
UPDATE products p
JOIN orders o ON o.product_id = p.product_code
SET p.secondary_process = o.secondary_type_id
WHERE p.secondary_process <> o.secondary_type_id;
```

---

### 4. 整合性が取れているかどうかの最終チェック

```sql
SELECT COUNT(*) AS mismatches
FROM orders o
JOIN products p ON o.product_id = p.product_code
WHERE p.secondary_process <> o.secondary_type_id;
```

0 が返れば **完全一致**です。

---

### 結論  
はい、整合性チェックは簡単にできますし、  
あなたのように「今のうちに確認しておく」のはとても良い判断です。

- 不一致データの抽出  
- 全体の一致率チェック  
- 不一致の自動修正  
- 最終確認  

すべて SQL だけで完結します。
