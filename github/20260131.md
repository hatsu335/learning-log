## [`push`後の変更]

### 1. 間違えて push してしまったファイルを取り消す方法

### ■ A. GitHub から完全に削除したい場合（履歴にも残したくない）
これは **「履歴を書き換える」操作**になるので注意が必要だけど、個人リポジトリなら問題ない。

### 手順
```bash
git rm ファイル名
git commit -m "Remove wrong file"
git push
```

これで最新のコミットからは削除されるけれど、**過去のコミットには残る**。

---

### ■ B. 過去のコミットからも完全に消したい（機密情報を誤ってpushした場合など）
これは **git filter-repo** や **BFG Repo-Cleaner** を使う方法になる。  
ただし操作が重いので、必要なときにだけ使うのが良い。

---

### 2. push したファイルを変更する方法

### 手順
1. ファイルを編集
2. コミット
3. push

```bash
git add ファイル名
git commit -m "Update file"
git push
```

これでGitHub上のファイルも更新される。

---

### 3. push したファイルを変更して、さらにファイル名も変更する方法

Gitはファイル名の変更も「変更」として扱うので、普通に操作すればOK。

### 手順
```bash
git mv old_name.py new_name.py
git add new_name.py
git commit -m "Rename file and update content"
git push
```

`git mv` を使うと、Gitが「これはリネームだ」と認識してくれる。

---

### まとめ（3つのケース）

| やりたいこと | コマンド |
|--------------|----------|
| 間違えてpushしたファイルを削除 | `git rm` → `commit` → `push` |
| pushしたファイルを修正 | `git add` → `commit` → `push` |
| pushしたファイルを修正＋名前変更 | `git mv` → `commit` → `push` |

---

### 補足：もし「push前の状態に戻したい」場合

例えば「間違えてコミットしてpushしてしまったから、push前の状態に戻したい」というケースなら：

```bash
git reset --hard HEAD~1
git push -f
```

ただし **`push -f`（強制push）は注意が必要**。  
他の人が同じリポジトリを使っている場合は絶対に使わない方がいい。
