# 🧭 仮想環境操作チートシート（conda / venv 両対応）

---

## 🟦 **1. conda での仮想環境操作**

### ■ 環境一覧を確認
```
conda info --envs
```

### ■ 新しい環境を作成
```
conda create -n <環境名> python=3.10
```

### ■ 環境をアクティベート（切り替え）
```
conda activate <環境名>
```

### ■ base に戻る
```
conda activate base
```

### ■ 環境を削除
```
conda remove -n <環境名> --all
```

### ■ その環境の pip を使う（確実な方法）
```
python -m pip list
python -m pip install <パッケージ名>
```

### ■ base が自動で有効にならない場合の設定
```
conda config --set auto_activate_base True
```

---

## 🟩 **2. venv での仮想環境操作**

### ■ 新しい環境を作成
```
python -m venv <環境フォルダ名>
```

### ■ 環境をアクティベート（切り替え）

#### Windows
```
<環境フォルダ名>\Scripts\activate
```

#### macOS / Linux
```
source <環境フォルダ名>/bin/activate
```

### ■ 環境を抜ける（共通）
```
deactivate
```

### ■ 環境を削除  
venv はフォルダを削除するだけで OK
```
rm -r <環境フォルダ名>
```
（Windows はエクスプローラで削除してもよい）

### ■ その環境の pip を使う（確実な方法）
```
python -m pip list
python -m pip install <パッケージ名>
```

# 🟦 conda と venv のメリット・デメリット比較（完全版）

## 🟩 **conda のメリット**
- **Python 以外の依存も管理できる**  
  → numpy, scipy, pytorch など C ライブラリ依存が強いものに強い  
- **環境の切り替えが簡単（conda activate）**
- **環境ごとに Python のバージョンを簡単に変えられる**
- **パッケージの互換性が高い（conda-forge）**
- **Windows でも安定して動く**

## 🟥 **conda のデメリット**
- **環境が重い（サイズが大きい）**
- **環境作成が遅い**
- **pip と混ぜると依存が壊れやすい**
- **VS Code が自動で認識しないことがある**

---

## 🟩 **venv のメリット**
- **Python 標準機能なので軽い・速い**
- **環境が小さい（最小限）**
- **pip との相性が完璧**
- **どの OS でも同じ操作で使える**
- **プロジェクトフォルダ内に置けるので管理しやすい**

## 🟥 **venv のデメリット**
- **Python 以外の依存は管理できない**  
  → numpy, scipy, pytorch などは OS のビルド環境が必要になることも  
- **環境の切り替えが OS で違う（Windows と mac/Linux）**
- **VS Code が自動で認識しないことがある**
- **conda のような依存解決の強さはない**

---

# 🟩 方法①：VS Code 左下から Python を選ぶ（最も簡単）

1. VS Code 左下の Python バージョンをクリック  
2. 使いたい環境（conda / venv）を選ぶ  
3. `.vscode/settings.json` が自動生成される

---

# 🟩 方法②：手動で `.vscode/settings.json` を作る（確実）

プロジェクトフォルダに `.vscode/settings.json` を作成して：

```json
{
    "python.defaultInterpreterPath": "/path/to/your/env/bin/python"
}
```

### conda の例（mac/Linux）
```
/Users/あなた/miniconda3/envs/myenv/bin/python
```

### conda の例（Windows）
```
C:\\Users\\あなた\\anaconda3\\envs\\myenv\\python.exe
```

### venv の例
```
<project>/venv/bin/python
```

これで VS Code は **そのフォルダを開いた瞬間にその Python を使う** ようになります。


を有効にすると、  
**新しいターミナルを開いたときに自動でその環境が activate される** ようになります。

# [pip と conda の併用ルール と conda-forge]

ここは Python 初学者〜中級者が必ずつまずくポイントなので、丁寧に整理します。

---

# 🎯 まず結論（最重要ポイント）
1. **conda 環境では、できるだけ conda install を優先する**  
2. **conda に無いパッケージだけ pip install を使う**  
3. **pip → conda の順で入れるのは絶対にNG**（環境が壊れる原因）  
4. **conda-forge は conda の巨大なパッケージ倉庫（公式より新しくて豊富）**

この4つを守れば、ほぼトラブルは起きません。

---

# 🟦 pip と conda の併用ルール（完全版）

## 🟩 ルール①：基本は conda install を優先する
conda 環境では、まずこう考えます。

```
conda install <パッケージ名>
```

理由は：

- conda は **依存関係を丸ごと解決してくれる**
- C ライブラリ（numpy, scipy, pytorch など）に強い
- pip より安全で壊れにくい

---

## 🟩 ルール②：conda に無いパッケージだけ pip install を使う
conda で検索して無ければ pip を使う。

### conda で検索
```
conda search <パッケージ名>
```

無ければ pip：

```
pip install <パッケージ名>
```

---

## 🟥 ルール③：pip → conda の順で入れるのは絶対にNG
これは環境破壊の元凶です。

### ❌ 悪い例
```
pip install numpy
conda install pandas
```

pip が入れた numpy と conda が入れた pandas の依存が衝突して  
**環境が壊れる（import エラーが出る）** ことがよくあります。

### ✔ 正しい順番
```
conda install numpy
conda install pandas
pip install <conda に無いもの>
```

---

## 🟩 ルール④：pip を使うときは必ず
```
python -m pip install ...
python -m pip list
```

これで **今の環境の pip** を確実に使えます。

---

## 🟥 ルール⑤：conda update conda / conda update --all は慎重に
環境が大きく変わるので、必要なときだけにするのが安全。

---

# 🟧 conda-forge とは何か？

## 🎯 一言で言うと：
> **conda の巨大なコミュニティ主導パッケージ倉庫（公式より新しくて種類が多い）**

### ✔ conda-forge の特徴
- 公式（default）より **パッケージが圧倒的に多い**
- 更新が早い（最新バージョンが手に入りやすい）
- 依存関係が統一されていて安定している
- データ分析・機械学習系はほぼ conda-forge が主流

### ✔ conda-forge からインストールする方法
```
conda install -c conda-forge <パッケージ名>
```

### ✔ 環境全体を conda-forge 優先にする方法（上級者向け）
```
conda config --add channels conda-forge
conda config --set channel_priority strict
```

---

# 🟫 conda vs pip の使い分け（あなた向けの最適解）

あなたの運用方針（base をメイン、プロジェクトごとに環境作成）なら：

### ✔ まず conda-forge で探す
```
conda search -c conda-forge <パッケージ名>
```

### ✔ あれば conda-forge から入れる
```
conda install -c conda-forge <パッケージ名>
```

### ✔ 無ければ pip
```
python -m pip install <パッケージ名>
```

これが最も安全で壊れにくい運用です。

# 🟩 まとめ（あなたが守るべきルール）

| 項目 | 結論 |
|------|------|
| conda と pip の優先順位 | **conda → pip** |
| pip → conda の順 | **絶対にNG** |
| conda-forge | conda の巨大な倉庫。最新で豊富 |
| pip を使うとき | **python -m pip** を使う |
| 環境が壊れないコツ | conda-forge を優先し、pip は最小限 |

# 🟥 1. conda 環境が壊れたときの復旧方法（重要度順）

環境が壊れる原因はほぼ以下のどれかです：

- pip → conda の順でインストールした  
- conda-forge と default が混ざった  
- 依存関係が衝突した  
- Python バージョンを途中で変えた  
- VS Code が別の Python を参照していた

壊れた環境は **直すより作り直した方が早い** のが現実です。  
ただし、復旧方法は段階的にあります。

---

## 🟩 方法①：pip が壊した場合の最速復旧（conda の再同期）
```
conda install --force-reinstall <パッケージ名>
```

pip が入れたものを上書きして、conda の依存関係に戻します。

---

## 🟩 方法②：環境全体を再構築（最も確実）
```
conda remove -n <環境名> --all
conda create -n <環境名> python=3.11
```

壊れた環境を直すより、作り直す方が圧倒的に早くて安全です。

---

## 🟩 方法③：環境のバックアップを作っておく（上級者向け）
環境を YAML で保存できます。

### バックアップ
```
conda env export > environment.yml
```

### 復元
```
conda env create -f environment.yml
```

これを使えば、環境を丸ごと再現できます。

---

## 🟩 方法④：conda-forge と default の混在を解消する
環境内のチャンネルを確認：

```
conda config --show channels
```

もし default と conda-forge が混ざっていたら、  
**どちらかに統一する** のが最も安全です。

# 🎯 結論：PySide6 は conda-forge から入れるのが最も安全
PySide6 は Qt という巨大な GUI フレームワークに依存しているため、pip で入れると以下の問題が起きやすいです：

- Qt のバイナリが OS と衝突  
- 依存ライブラリのバージョン不一致  
- conda の numpy / matplotlib と pip の PySide6 が衝突  
- VS Code が別の Python を参照して import エラー

conda-forge 版は **依存関係が完全に整備されている**ため、これらの問題がほぼ起きません。

---

# 🟦 PySide6 を conda-forge で安全にインストールする手順（最重要）

以下の手順を守れば、PySide6 はほぼ確実に動きます。

---

## 🟩 Step 1：新しい conda 環境を作る（推奨）
PySide6 は環境を汚しやすいので、専用環境を作るのが安全です。

```
conda create -n pyside6-env python=3.11
conda activate pyside6-env
```

---

## 🟩 Step 2：conda-forge を優先チャンネルにする（重要）
```
conda config --add channels conda-forge
conda config --set channel_priority strict
```

これで **default と混ざらず、依存が壊れない**。

---

## 🟩 Step 3：PySide6 を conda-forge からインストール
```
conda install -c conda-forge pyside6
```

これだけで Qt も含めてすべて自動で整います。

---

## 🟩 Step 4：インストール確認
```
python -c "import PySide6; print(PySide6.__version__)"
```

エラーが出なければ成功。

---

# 🟧 pip 版 PySide6 を使ってはいけない理由（あなたの過去のトラブルの原因）

pip 版 PySide6 は：

- Qt の DLL / SO ファイルを pip が直接落としてくる  
- OS の Qt と衝突することがある  
- conda の numpy / matplotlib と依存が噛み合わない  
- PySide6 のバージョンが OS によって動いたり動かなかったりする  
- VS Code が別の Python を参照すると import エラー

特に Windows では **pip 版 PySide6 が動かないケースが多い**です。

あなたが以前 PySide6 でトラブったのは、ほぼ確実にこの問題です。
