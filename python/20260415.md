## [Pandas.read_sql()による型タイプについて]

**「データベースの型は *完全には* 保証されない」**

`pandas.read_sql()` は便利ですが、**DB の型をそのまま忠実に再現するわけではありません**。  
Python（pandas）の型推論によって、状況次第で型が変わることがあります。  
ここを理解しておくと、後々のバグを避けられます。  

---

## 結論（短く）
- **DB の型は pandas では保証されない**
- pandas は **独自の型推論** を行う
- 特に **日付・整数・NULL を含む列** は型が変わりやすい
- 必要なら **dtype を明示指定するのが安全**

---

## なぜ型が変わるのか（pandas の仕様）

### 1. NULL（NULL / NaN）があると整数が float になる
DB の `INT` カラムでも、NULL があると pandas はこう判断します：

```
INT + NULL → float64
```

例：

| DB | pandas |
|----|--------|
| INT | float64（NULL がある場合） |

---

### 2. 日付型（DATE / DATETIME）は object になることがある
DB の `DATE` や `DATETIME` は、  
pandas がうまく推論できないと **object（文字列）** になります。

例：

| DB | pandas |
|----|--------|
| DATETIME | datetime64[ns] または object |

---

### 3. VARCHAR / TEXT は基本的に object（文字列）
これはほぼ問題なし。

---

### 4. DECIMAL / NUMERIC は float になることがある
精度が必要な金額などは注意。

---

## では「DB の型を担保したい」場合はどうする？

### 方法1：`dtype` を明示指定する（最も確実）

```python
df = pd.read_sql(
    query,
    self.engine,
    dtype={
        "quantity": "Int64",   ##NULL を許容する整数
        "product_id": "Int64",
        "process_due": "datetime64[ns]",
    },
    parse_dates=["process_due", "expected_due"]
)
```

#### 特におすすめの型
- **Int64**（NULL を許容する整数）
- **string**（pandas の新しい文字列型）
- **datetime64[ns]**

---

### 方法2：読み込み後に変換する

```python
df["quantity"] = pd.to_numeric(df["quantity"], errors="coerce").astype("Int64")
df["process_due"] = pd.to_datetime(df["process_due"], errors="coerce")
```

---

## 実務でよく起きる「型の落とし穴」

#### INT が float になる
→ NULL があると float64 に変換される

#### DATETIME が文字列になる
→ DB のフォーマットが pandas の推論に合わない

#### DECIMAL が float になり精度が落ちる
→ 金額計算で誤差が出る

#### VARCHAR が object になり、空白や None が混ざる
→ 前処理が必要

---

## まとめ（重要ポイントだけ）

- **pandas.read_sql は DB の型を完全には再現しない**
- pandas は **独自の型推論** を行う
- 特に **整数・日付・NULL** は型が変わりやすい
- 型を保証したいなら **dtype を明示指定するのが最も安全**
