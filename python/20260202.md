## [タイピング効率化]

### VS Codeでタイピングの負担を減らし、「肩凝り」を劇的に解消するための厳選ショートカット

これらを使うと、マウスに手を伸ばす回数が減り、タイピングが「点」ではなく「流れ」に変わります。

---

### 1. 爆速でコードを補完・修正する

まずは、タイピング量を物理的に減らすための基本技です。

| ショートカット | 動作 | 活用シーン |
| --- | --- | --- |
| **`Tab`** | **補完の決定** | `pd.r` まで打って候補が出たら `Tab` で確定。 |
| **`Ctrl` + `Space**` | **補完候補を強制表示** | 候補が消えてしまった時に、再度呼び出せます。 |
| **`Ctrl` + `Enter**` | **次の行へ挿入** | 行の途中にカーソルがあっても、即座に改行して下の行へ。 |
| **`Alt` + `↑` / `↓**` | **行の入れ替え** | コードを数行上に動かしたい時、コピペ不要で移動できます。 |

---

### 2. 編集のストレスを減らす

同じ単語を何度も打ち直したり、一文字ずつ消したりするのは肩凝りの原因です。

### **一括選択 (`Ctrl` + `D`)**

同じ変数名（例えば `new` など）を一気に書き換えたい時に使います。

1. 書き換えたい単語にカーソルを置く。
2. `Ctrl` + `D` を押すごとに、同じ単語が次々と選択される。
3. そのまま打つと、**選択した箇所すべてが同時に書き換わります。**

### **単語単位の移動・削除 (`Ctrl` + `←` / `→` / `Backspace`)**

一文字ずつチマチマ動かすのではなく、単語（塊）ごとにスキップします。

* **`Ctrl` + `←`/`→**`：単語の先頭にジャンプ。
* **`Ctrl` + `Backspace**`：単語まるごと削除。

---

### 3. 画面管理（マウスを捨てよう）

コードが長くなってくると、画面のスクロールだけで疲れます。

* **`Ctrl` + `B**`：左側のサイドバー（ファイル一覧）を開閉します。画面を広く使いたい時に。
* **`Ctrl` + `/**`：選択した行を一瞬で**コメントアウト**（無効化）します。
* **`Ctrl` + `P**`：ファイル名を入力して直接ファイルを開きます。

---

### 4. プロの裏技：定義へジャンプ (`F12`)

模写している時、「この `DataManager` ってどこで定義したっけ？」と思ったら、その単語の上で **`F12`** を押してください。
そのクラスや関数が作られた場所まで、一瞬でワープします。

---

### おすすめの練習方法

一度に全部覚えるのは大変なので、まずは **`Ctrl` + `D`（一括選択）** と **`Tab`（補完）** だけを意識して使ってみてください。

## [`sys.frozen` とは何を判定しているのか？]

Honeycomb_management_system.py
```python
class DataManager(object):
    def __init__(self):
        if getattr(sys, 'frozen', False): # この手段は復習必要
            self.base_dir = os.path.dirname(sys.executable)
            # self.base_dir = sys._MEIPASS
        else:
            self.base_dir = os.path.dirname(__file__)

        self.data_dir = os.path.join(self.base_dir, 'masters')
        self.product_csv = os.path.join(self.data_dir, 'products.csv')
        self.stock_csv = os.path.join(self.data_dir, 'stock.csv')
        self.orders_csv = os.path.join(self.data_dir, 'orders.csv')
        self.prices_csv = os.path.join(self.data_dir, 'process_prices.csv')
        self.load_all()
```

一言で言うと、**「いま動いているのは、生のPythonファイル（.py）か、それとも配布用に固めた実行ファイル（.exe）か？」**を判別しています。

### なぜこの処理が必要なのか？

プログラムが読み込む「画像」や「CSV」などのデータは、実行環境によって場所が変わってしまいます。

* **開発中 (.py):** 自分のPCのフォルダ（スクリプトと同じ場所）にある。
* **配布後 (.exe):** ユーザーのPCで、どこにインストールされるか分からない。

---

### 図解：パス判定の仕組み

このコードは、以下のような二段構えのロジックになっています。

### ① 配布用（exe化されている）場合

```python
self.base_dir = os.path.dirname(sys.executable)

```

プログラムが「パッケージ化」されている時、`sys.frozen` は **True** になります。この時、データを探すべき場所は「exeファイル本体が置かれている場所」になります。

### ② 開発中（.pyのまま実行）の場合

```python
self.base_dir = os.path.dirname(__file__)

```

普通にVS Codeなどで実行している時は、`__file__`（今開いているこのファイル自体の場所）を基準にします。

---

### 結局、何をしているのか？

この数行のおかげで、**「自分のPCで開発している時も、誰かにexeファイルを渡して使ってもらう時も、設定を変えずに同じようにデータ（mastersフォルダ）を見つけられる」**ようになっています。

まさに「どこでも動く」ための魔法のコードですね！
