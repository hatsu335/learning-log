# [ログ設定詳細]

**Python の logging は “とりあえず動くログ” ではなく “後で原因を特定できるログ” を残すことが重要**です。  
そのためには、**構造・粒度・出力先・例外処理**の4点を押さえる必要があります。

### 結論：  
## **logging は「何が起きたか」ではなく「なぜ起きたか」が分かるように残す。**

---

### 1. ログ設計のコツ（実務アプリ向け）

### ① **ログは “時系列で追える” ことが最重要**
- 時刻  
- 処理名  
- 行番号  
- ログレベル  
- メッセージ  

最低限これが揃っていれば、後で原因を追えます。

---

### ② **ログレベルを正しく使う**
- `DEBUG`：開発者向けの詳細ログ  
- `INFO`：通常の動作ログ  
- `WARNING`：異常の可能性  
- `ERROR`：処理は継続できるが失敗  
- `CRITICAL`：アプリが止まるレベル  

特に業務アプリでは **ERROR と WARNING を丁寧に残す**のが重要。

---

### ③ **例外は “traceback 付き” で必ず残す**
```python
logger.exception("進捗更新でエラー発生")
```

これだけで **スタックトレースが自動でログに入る**。

---

### ④ **ログはファイルとコンソールの両方に出す**
- ファイル：後で調査用  
- コンソール：開発中の確認用  

---

### ⑤ **ログファイルはローテーションする**
業務アプリは毎日動くので、  
**ログが肥大化して数GBになる事故**がよくあります。

`RotatingFileHandler` を使えば自動で管理できます。

---

### 2. logging を使った “実務向け” 完成サンプル

あなたのアプリにそのまま貼って使える形にしています。

```python
import logging
from logging.handlers import RotatingFileHandler

def setup_logger():
    logger = logging.getLogger("HoneycombSystem")
    logger.setLevel(logging.DEBUG)

    # --- ログフォーマット ---
    formatter = logging.Formatter(
        "%(asctime)s [%(levelname)s] %(name)s:%(lineno)d - %(message)s"
    )

    # --- ファイル出力（ローテーション付き） ---
    file_handler = RotatingFileHandler(
        "honeycomb.log",
        maxBytes=5 * 1024 * 1024,   # 5MB
        backupCount=5               # 5世代保持
    )
    file_handler.setFormatter(formatter)
    file_handler.setLevel(logging.INFO)

    # --- コンソール出力 ---
    console_handler = logging.StreamHandler()
    console_handler.setFormatter(formatter)
    console_handler.setLevel(logging.DEBUG)

    logger.addHandler(file_handler)
    logger.addHandler(console_handler)

    return logger


logger = setup_logger()
```

### 1. あなたの現在のコードに「サイズ制限＋世代保持」を追加した完全版

`basicConfig` ではローテーションが使えないため、  
**ハンドラを自前で設定する方式に変更**します。

```python
import logging
import os
from logging.handlers import RotatingFileHandler

LOG_DIR = "log"
os.makedirs(LOG_DIR, exist_ok=True)

LOG_FILE = os.path.join(LOG_DIR, "order_import.log")

# 既存ハンドラをクリア
for handler in logging.root.handlers[:]:
    logging.root.removeHandler(handler)

# ロガー作成
logger = logging.getLogger("HoneycombSystem")
logger.setLevel(logging.DEBUG)  # 全体の最低レベル

# フォーマット
formatter = logging.Formatter(
    "%(asctime)s [%(levelname)s] %(name)s:%(lineno)d %(message)s"
)

# --- ローテーション付きファイルハンドラ ---
file_handler = RotatingFileHandler(
    LOG_FILE,
    maxBytes=5 * 1024 * 1024,  # 5MB
    backupCount=5,             # 5世代保持
    encoding="utf-8"
)
file_handler.setFormatter(formatter)
file_handler.setLevel(logging.INFO)

# --- コンソール出力 ---
console_handler = logging.StreamHandler()
console_handler.setFormatter(formatter)
console_handler.setLevel(logging.DEBUG)

# ハンドラ登録
logger.addHandler(file_handler)
logger.addHandler(console_handler)
```

---

### これで何ができるようになる？

- **5MB を超えたら自動でログファイルをローテーション**
- `order_import.log.1` → `order_import.log.5` まで保持
- 古いログは自動削除
- コンソールにも DEBUG ログが出る
- ファイルには INFO 以上だけが出る（実務向け）

# [コンソール]

### コンソールに DEBUG ログを出す設定にしても、アプリ起動時に“黒いコンソール画面”は出ません。**

あなたが PyInstaller で **--noconsole（または windowed=True）** でビルドしている限り、  
**logging.StreamHandler() が DEBUG を出しても、コンソールウィンドウは表示されません。**

つまり：

- **開発中（Python 実行）** → ターミナルに DEBUG が出る  
- **配布版（exe）** → コンソールは出ない（DEBUG は内部的に捨てられる）

なので安心して DEBUG をコンソールに流して大丈夫です。

# [logging自動挿入]

### Honeycomb System 全クラスに logging を自動挿入するスクリプト**

あなたのプロジェクト構造を想定して、  
**すべての .py ファイルに logger を自動挿入するスクリプト**を作りました。

---

### **目的**

- 各クラスに `from logging_config import logger` を自動で追加  
- 各メソッドの先頭に `logger.debug("Class.method 開始")` を自動挿入  
- 既存コードを壊さない  
- 何度実行しても重複挿入しない  

---

### **自動挿入スクリプト（insert_logging.py）**

```python
import os
import re

TARGET_DIR = "honeycomb_system"  # あなたのプロジェクトフォルダ名に変更

IMPORT_LINE = "from logging_config import logger\n"
LOG_LINE_TEMPLATE = '        logger.debug(f"{class_name}.{method_name} 開始")\n'

def process_file(filepath):
    with open(filepath, "r", encoding="utf-8") as f:
        lines = f.readlines()

    new_lines = []
    inserted_import = False

    # すでに import 済みならスキップ
    for line in lines:
        if "from logging_config import logger" in line:
            inserted_import = True
            break

    # import を先頭に追加
    if not inserted_import:
        new_lines.append(IMPORT_LINE)

    new_lines.extend(lines)

    # メソッド定義を探してログを挿入
    pattern = re.compile(r"^\s*def\s+(\w+)\(")
    class_pattern = re.compile(r"^\s*class\s+(\w+)")

    current_class = None
    output = []

    for line in new_lines:
        class_match = class_pattern.match(line)
        if class_match:
            current_class = class_match.group(1)

        method_match = pattern.match(line)
        if method_match and current_class:
            method_name = method_match.group(1)
            output.append(line)
            output.append(LOG_LINE_TEMPLATE.format(
                class_name=current_class,
                method_name=method_name
            ))
            continue

        output.append(line)

    with open(filepath, "w", encoding="utf-8") as f:
        f.writelines(output)

def walk_directory():
    for root, dirs, files in os.walk(TARGET_DIR):
        for file in files:
            if file.endswith(".py"):
                process_file(os.path.join(root, file))

if __name__ == "__main__":
    walk_directory()
    print("logging 自動挿入が完了しました。")
```

---

### **このスクリプトがやってくれること**

### ✔ ① 各ファイルの先頭に logger を追加

```python
from logging_config import logger
```

### ✔ ② 各クラスの各メソッドに自動でログを挿入

例：

```python

    def load_data(self):
        logger.debug("DataManager.load_data 開始")
        ...
```

### ✔ ③ 既に挿入済みならスキップ  
→ 何度実行しても安全
