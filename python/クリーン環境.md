# [EXE化前の必須手順]

ここは手順を曖昧にするとまた環境が汚れるので、**確実に再現できる方法**で説明します（Windows前提）。

---

# ① クリーン環境とは何か（前提）

目的はこれです：

> **「必要なモジュールだけが入った独立環境」を作る**

👉 Anacondaや既存Pythonとは**完全に切り離す**のがポイント

---

# ② 手順（そのまま実行できます）

## ■ ① 作業フォルダを用意

まず任意の場所にフォルダ作成

例：

```text id="v3kjp6"
C:\work\honeycomb_build
```

---

## ■ ② コマンドプロンプトを開く

そのフォルダで：

```bash id="p4q4os"
cd C:\work\honeycomb_build
```

---

## ■ ③ 仮想環境（venv）作成

```bash id="lv1r8g"
python -m venv build_env
```

👉 `build_env` フォルダが作成される

---

## ■ ④ 仮想環境を有効化

```bash id="jyz2iy"
build_env\Scripts\activate
```

成功すると：

```text id="jy8fsn"
(build_env) C:\work\honeycomb_build>
```

👉 これが重要な状態

---

## ■ ⑤ pipアップデート

```bash id="eh9a0q"
python -m pip install --upgrade pip
```

---

## ■ ⑥ 必要最小だけインストール

```bash id="ijbksq"
pip install pyinstaller sqlalchemy pymysql reportlab pyyaml pandas openpyxl python-dateutil
```

---

## ■ ⑦ 確認（ここ必須）

```bash id="7d9h7j"
pip list
```

👉 余計なものが入っていないか確認

---

# ③ スクリプトを配置

このフォルダにコピー：

```text id="1c3sqz"
honeycomb_management_system.py
delivery_pdf.py
estimate_pdf.py
戦闘機.ico
```

※ config.yamlは後でOK

---

# ④ ビルド実行

```bash id="0fpv0n"
pyinstaller ^
--noconsole ^
--icon=戦闘機.ico ^
--hidden-import=pymysql ^
--hidden-import=reportlab ^
honeycomb_management_system.py
```

---

# ⑤ 実行テスト

```text id="ru8k4r"
dist\honeycomb_management_system\
```

この中に：

* exe
* ライブラリ群

👉 ここに `config.yaml` を配置

---

# ⑥ よくあるミス（重要）

## ■ ミス①：Anacondaのpythonを使っている

確認：

```bash id="tq42s6"
where python
```

👉 理想：

```text id="3vx1dt"
...build_env\Scripts\python.exe
```

---

## ■ ミス②：activate忘れ

```text id="c3mcv6"
(build_env) が表示されていない
```

👉 これだと意味がない

---

## ■ ミス③：過去のbuildが残っている

```bash id="0v7v9k"
rmdir /s /q build
rmdir /s /q dist
del *.spec
```

---

# ⑦ クリーン環境の削除方法

不要になったら：

```bash id="bbq6t9"
rmdir /s /q build_env
```

👉 これで完全削除

---

# ⑧ 実務的な運用（重要）

今後はこう分けます：

```text id="4r6t0r"
開発環境（Anaconda）
→ コードを書く

ビルド環境（venv）
→ exe作る専用
```

👉 混ぜない

---

# ⑨ ここまでできれば

* サイズ問題 → 解決
* 依存関係 → 明確
* トラブル → 激減

---

# [Powershellでの操作]

はい、**PowerShellで問題ありません**。むしろ最近はPowerShellを使う人の方が多いです。

ただし、**venvの有効化コマンドが少し違う**のでそこだけ注意してください。

---

# ① PowerShellでの手順（重要ポイント）

## ■ 仮想環境の作成（同じ）

```powershell id="9o7bmi"
python -m venv build_env
```

---

## ■ 有効化（ここが違う）

### コマンドプロンプト（参考）

```cmd
build_env\Scripts\activate
```

### PowerShell（これを使う）

```powershell id="xf0v5n"
.\build_env\Scripts\Activate.ps1
```

---

## ■ 成功するとこうなる

```text id="x5h6j9"
(build_env) PS C:\work\honeycomb_build>
```

👉 `(build_env)` が出ればOK

---

# ② 実行ポリシーエラーが出た場合

PowerShell特有の問題です：

```text id="dn7j0t"
スクリプトの実行が禁止されています
```

---

## ■ 解決方法（1回だけでOK）

```powershell id="r38l3u"
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

その後：

```powershell id="9yhhqk"
.\build_env\Scripts\Activate.ps1
```

---

# ③ それ以外は同じ

あとは全部同じです：

```powershell id="kz4f3i"
pip install ...
pyinstaller ...
```

---

# ④ 実務的な補足

PowerShellの利点：

* コマンド履歴が使いやすい
* パス操作が楽
* スクリプト化しやすい

👉 ビルド作業とは相性が良い

---

# 結論

* PowerShellでOK
* 有効化コマンドだけ注意
* 実行ポリシーエラーが出たら設定変更

---

この状態でビルドすれば、**環境分離は正しくできています**。
