# ① MySQLを別PCへ移行する方法（標準手順）

最も確実でトラブルが少ないのは **論理バックアップ（mysqldump）** です。

---

## ■ 手順（これをそのままやればOK）

### ① バックアップ（移行元PC）

```bash
mysqldump -u ユーザー名 -p データベース名 > backup.sql
```

例：

```bash
mysqldump -u root -p honeycomb_db > backup.sql
```

---

### ② backup.sql を移動

* USB / ネットワーク / NAS などでコピー

---

### ③ 移行先でDB作成

```bash
mysql -u root -p
```

```sql
CREATE DATABASE honeycomb_db;
```

---

### ④ リストア（移行先PC）

```bash
mysql -u root -p honeycomb_db < backup.sql
```

---

## ■ これで移行されるもの

* テーブル構造
* データ
* インデックス

---

## ■ 移行されないもの（注意）

* ユーザー（権限）
* MySQL設定（my.cnf）

👉 必要なら手動で作成：

```sql
CREATE USER 'user'@'%' IDENTIFIED BY 'password';
GRANT ALL PRIVILEGES ON honeycomb_db.* TO 'user'@'%';
```

# 次に詰めると良いこと

もしやるなら：

* NASの機種（Synology / QNAP など）
* 同時接続数
* 使用頻度

これが分かれば、**最適構成（Docker含めて）**まで具体的に設計できます。


現在はCSVで管理しているアプリで、アプリもCSVファイルもNASにおいて複数台のPCで運用しています。できればそうしたかったのですがなかなかハードルが高そうですね。


その構成（**CSV＋NAS共有＋複数PC**）から一気にDBへ置き換えるのは、確かに難易度が上がります。特にあなたのアプリは「更新・追記・比較」をしているので、**同時アクセス制御**が絡むからです。

結論を先に整理します：

> **今の運用に近い形を保つなら「NAS上でMySQLを動かす」か「PC側にDBを置いて接続」のどちらかに寄せる必要があります**
> CSVと同じ感覚（ファイル共有型）でDBを扱うのは基本的に無理です

---

# ① なぜCSVはできてDBは難しいのか

CSV運用：

```text
NAS上のファイルを直接読む・書く
```

👉 OSのファイル共有で成立

---

DB運用：

```text
DBサーバーに対してクエリを投げる
```

👉 サーバープロセスが必要

---

つまり：

* CSV → ファイル単位の共有
* MySQL → プロセス単位の管理

👉 **設計思想が根本的に違う**

---

# ② 今の構成の「良いところ」

正直これは優秀です：

* セットアップが簡単
* NASに置くだけで共有
* バックアップしやすい

---

# ③ ただしCSVの限界

あなたのコードを見る限り、すでに：

* 更新処理（UPDATE）
* 重複チェック
* データ整形

👉 **DB向きの処理になっています**

CSVで続けると：

* 排他制御ができない

# ⑩ 次にやるべきこと

まずはどちらにするか決める：

1. PC1台をDBサーバーにする
2. NASにDockerでMySQL入れる

---

もしNASの機種（例：Synology DS220+など）が分かれば、
**「実際に動く構成」まで具体的に手順化できます**。


1台のPCに構築して、他のPCはベースPCへ接続する形を選択しようと思います。
ただし、問題があって、現在のネットワーク環境がPC間のアクセスをしていなくて、すべてのPCがサーバーかNASへのアクセスにとどめています。実際にPC間のアクセスも一部はできるのですが、セキュリティを強化してからなかなかうまくいかなくてそのままの状態です。そこが悩みの種です。


その懸念はもっともです。
ただ、前提を一つ整理すると：

> **「PC間アクセスを完全に開ける」必要はありません**
> 必要なのは **“MySQLのポート（3306）だけを限定的に通す”** ことです

つまり、セキュリティを崩さずに実現できます。

---

# ① 目標とする最小構成

```text
[クライアントPC] ──(TCP 3306のみ)──> [DB用PC]
```

* ファイル共有：不要
* リモートデスクトップ：不要
* ICMP(ping)：不要でもOK

👉 **3306だけ通せば成立**

---

# ② やること（全体像）

やる作業は3つだけです：

1. MySQL側の待受設定
2. ユーザー権限設定
3. Windowsファイアウォール開放

---

# ③ MySQL側の設定（重要）

## ■ my.ini / my.cnf

```ini
[mysqld]
bind-address = 0.0.0.0
```

👉 これをやらないと外部から接続できません

---

# ④ ユーザーの接続許可

今こうなっている可能性が高い：

```sql
'user'@'localhost'
```

👉 これだと外から接続不可

---

## ■ 修正

```sql
CREATE USER 'user'@'%' IDENTIFIED BY 'password';
GRANT ALL PRIVILEGES ON honeycomb_db.* TO 'user'@'%';
FLUSH PRIVILEGES;
```

---

## ■ セキュリティ強化版（推奨）

```sql
CREATE USER 'user'@'192.168.1.%' IDENTIFIED BY 'password';
```

👉 同一ネットワーク内だけ許可

---

# ⑤ Windowsファイアウォール設定（核心）

## ■ DB用PCで実施

PowerShell（管理者）：

```powershell
New-NetFirewallRule `
  -DisplayName "MySQL 3306" `
  -Direction Inbound `
  -Protocol TCP `
  -LocalPort 3306 `
  -Action Allow
```

---

## ■ さらに安全にする（強く推奨）

接続元IPを限定：

```powershell
New-NetFirewallRule `
  -DisplayName "MySQL 3306 limited" `
  -Direction Inbound `
  -Protocol TCP `
  -LocalPort 3306 `
  -RemoteAddress 192.168.1.10,192.168.1.11 `
  -Action Allow
```

---

# ⑥ クライアント側設定

SQLAlchemy接続文字列：

```python
mysql+pymysql://user:password@192.168.1.100:3306/honeycomb_db
```

👉 `192.168.1.100` = DB用PCのIP

* 問題の本質は「ネットワーク許可範囲」
